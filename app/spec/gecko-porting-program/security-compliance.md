# 安全与合规评审：Gecko for HarmonyOS

**版本**: 1.0
**日期**: 2026-11-17
**评审范围**: JIT/可执行内存、进程模型与 fork/exec、应用商店政策、权限与隐私
**结论摘要**:

| 约束 | 结论 | 依据 | 阻塞门禁 |
|---|---|---|---|
| JIT（可执行内存） | **待审批**（解释器路径可行，ACL 路径待批） | 见 §1 | G1 |
| fork/exec 与 e10s 沙箱 | **不可行**，已确定降级方案（单进程） | 见 §2 | G2 |
| `ChildProcess` 受限多进程 | **待验证**（能力存在，但与 Gecko 模型差异大） | 见 §2.3 | G6 |

## 1. JIT 与可执行内存

### 1.1 平台约束

- 第三方应用默认**不允许**申请可执行匿名内存（`PROT_EXEC` + `MAP_ANONYMOUS`）。
- 例外路径是受限 ACL 权限 `ohos.permission.kernel.ALLOW_EXECUTABLE_FORT_MEMORY`，
  需要应用市场/系统侧审批，且设备可能处于"坚盾模式"（全局禁用 JIT）。
- 未获批就声明该权限会导致**安装失败**，因此本项目在获批前**不写入** `module.json5`。

### 1.2 三条可选路径

| 路径 | 机制 | 可行性 | 性能影响 | 本项目管理方式 |
|---|---|---|---|---|
| **A. 纯解释器** | SpiderMonkey `--disable-jit`，仅 bytecode 解释执行 | **可行，默认路径** | 相对 JIT 约 3-10× 慢（依赖负载） | M1 默认；G1 用基准实测 |
| **B. ACL + JIT** | 申请 ACL，`mprotect(PROT_EXEC)` 后可启用 Ion/Baseline | **待审批** | 接近桌面 Firefox | ACL 获批 + 设备检测通过才启用 |
| **C. 混合模式** | 默认解释器；运行时检测 ACL + 坚盾状态，满足条件才开 JIT | **推荐终态** | 视设备而定 | M1 之后实现检测与开关 |

### 1.3 实施规则（硬）

1. `module.json5` **不得**出现 `ohos.permission.kernel.ALLOW_EXECUTABLE_FORT_MEMORY`，
   直到拿到书面批准（见 §5 审计记录）。
2. 代码中所有 JIT 启用点必须经过同一个检测函数，输入包含：
   ACL 是否授予、系统是否处于坚盾模式、`mmap(PROT_EXEC)` 自检是否成功。
3. 任一检测失败 → 明确降级到解释器，并在 `getVersion()`/日志中暴露 `jitMode=interpreter`。
4. `evaluateScript` 等调试入口在生产构建可关闭，避免成为攻击面。

### 1.4 性能补偿（解释器模式下）

- 字节码缓存 + 编译缓存复用；
- 降低跨进程/跨线程同步开销（单进程模型下收益明显）；
- 首屏关键路径预编译（`JS::Compile` 结果缓存）；
- 在 `performance-baseline.md` 里把"解释器模式"作为基线口径，ACL 通过后再单独记录 JIT 数据。

### 1.5 风险与触发条件

| 项 | 内容 |
|---|---|
| 风险 | ACL 被拒 + 解释器性能不足 → 体验不可接受 |
| 触发 | G1 基准中 JS 密集页面可交互时间 > 3× 参考值 |
| 动作 | 启动热路径优化专项；若仍不达标，按停止条件评估降级（限制重 JS 站点能力提示） |

## 2. 进程模型、fork/exec 与沙箱

### 2.1 平台约束

- 普通应用**禁止** `fork()` / `exec()` 任意可执行文件。
- 自定义可执行文件在可写目录运行返回 `EPERM`（本项目已实测）。
- 因此 Firefox 的 **e10s**（内容进程 + 沙箱）模型**不能照搬**。

### 2.2 三种方案对比

| 方案 | 可行性 | 隔离强度 | 崩溃影响 | 采用阶段 |
|---|---|---|---|---|
| **单进程（默认）** | 可行 | 弱（依赖应用沙箱 + 站点级逻辑隔离） | 整应用崩溃 | M1-M5 |
| 受限多进程（`ChildProcess`） | 待验证 | 中（独立进程、无 UI、IPC） | 内容进程崩溃不影响 UI | M6 评估 |
| 完整 e10s 沙箱 | 不可行 | 高 | — | 不采用 |

### 2.3 单进程模型下的补偿措施

1. **崩溃隔离**：引擎调用全部包在 NAPI 边界内；native crash 由系统处理，UI 侧记录最后状态并在重启后恢复标签。
2. **资源限制**：单标签内存上限、标签休眠/丢弃（后台标签释放渲染资源）。
3. **站点隔离降级**：不做进程级隔离，改为同源策略 + 权限提示 + 下载/文件访问白名单。
4. **进程抽象层**：代码中保留 `ProcessHost` 接口（单进程实现），M6 可替换为 `ChildProcess` 实现。

### 2.4 `ChildProcess`（M6 评估项）

- 能力：创建无 UI 子进程、双向 IPC。
- 与 Gecko 的差距：Gecko 的 content process 需要共享内存、文件描述符传递、复杂的 IPC 协议；
  `ChildProcess` 是否支持 fd 传递与共享内存需在 M6 做 spike。
- 决策门：G6 前给出"可用/不可用"结论；不可用则长期维持单进程 + 应用层隔离。

### 2.5 安全结论

- **e10s 沙箱：不可行**（平台禁止 fork/exec，且不提供等价能力）。
- **单进程：可行**，但必须在产品文档中明确"崩溃影响整应用"的已知限制。
- **受限多进程：待验证**，不作为首版承诺。

## 3. 应用商店政策与上架路径

### 3.1 关键不确定性

平台不提供第三方 WebView 内核接入位，因此本产品是"应用内自绘内核浏览器"。
该类应用的上架政策需要市场书面确认，不能假设默许。

### 3.2 需要确认的问题（提交给市场/法务）

1. 自绘内核浏览器是否允许上架？是否需要额外资质或审核材料？
2. 是否要求提供内核安全更新承诺（CVE 响应 SLA）？
3. 是否限制下载、脚本执行、证书自定义等浏览器核心能力？
4. 是否需要公开"内核来源与版本"（Firefox/Gecko + 修改说明）？
5. 隐私政策、权限说明、数据处理清单是否有浏览器专项要求？

### 3.3 上架路径（按优先级）

| 路径 | 说明 | 触发条件 |
|---|---|---|
| **A. 正常上架** | 自绘 Gecko 内核 + 完整隐私合规材料 | 市场书面允许 |
| **B. 条件上架** | 关闭部分能力（自定义证书、扩展、DRM）换取通过 | 市场提出限制 |
| **C. 降级 ArkWeb** | 保留 UI/数据层，引擎替换为系统内核 | 市场明确拒绝自绘内核 |

路径 C 的技术前提：`GeckoService` 已抽象为 facade，UI 不直接依赖 Gecko 类型，替换引擎只需改 service 层实现。

### 3.4 品牌与许可

- 使用 Firefox/Gecko 代码需遵守 MPL 2.0：修改文件需保留许可声明，分发需提供源码获取方式。
- 产品名称/图标不得让用户误认为是 Mozilla 官方产品；品牌使用边界需法务确认（决策包 D-5）。

## 4. 权限与隐私合规

### 4.1 权限声明策略（最小化）

| 能力 | 是否需要系统权限 | 方案 |
|---|---|---|
| 网络访问 | `ohos.permission.INTERNET` | 引擎网络必需（M4 声明） |
| 文件下载/保存 | 不需要（使用 picker / 应用沙箱） | `DocumentViewPicker` 保存到用户选择位置 |
| 读取用户文件（上传） | 不需要 | `DocumentViewPicker` 选择 |
| 相机/麦克风（WebRTC） | `user_grant` | 首版不做 WebRTC，不声明 |
| 位置（地理定位） | `user_grant` | 首版不做，不声明 |
| 通知（下载完成） | 可选 | 首版用应用内提示，不声明 |
| JIT ACL | 受限 ACL | **未获批不声明**（§5） |

规则：`user_grant` 权限必须在 `module.json5` 同时提供 `reason`（字符串资源）与 `usedScene`；
没有真实使用场景的权限一律不声明。

### 4.2 隐私清单（上架材料）

- [ ] 收集的数据类型：无（首版不做遥测）／如做崩溃上报需列明字段
- [ ] 数据用途与保留期限
- [ ] 第三方 SDK 清单（Gecko 内嵌 NSS 等需说明）
- [ ] 用户数据删除路径（清除历史/书签/缓存/profile）
- [ ] 隐私模式说明：不写历史、不落 cookie（会话级）、退出清理
- [ ] 权限使用说明（逐项）
- [ ] 儿童/青少年保护声明（如适用）

### 4.3 应用内数据隔离

| 数据 | 位置 | 隔离方式 |
|---|---|---|
| 设置 | Preferences | 命名空间 `browser.<domain>.<key>` |
| 书签/历史/下载 | RelationalStore | 按 `profileId` 分区 |
| 引擎 profile | `filesDir/gecko-profile/<profileId>` | 每 profile 独立目录 |
| 隐私模式 profile | 临时目录 | 退出即清理，不写历史 |
| 账户密钥 | HUKS / Asset Store | 仅存引用，不落明文 |

### 4.4 日志与遥测约束

- 日志不得包含 URL 明文（可用哈希/域名）、cookie、token、用户输入。
- `hilog` 使用固定 domain，禁止在 release 输出调试级敏感内容。
- 崩溃上报（如启用）必须脱敏并给出关闭开关。

## 5. 权限审计记录（T036）

审计对象：`entry/src/main/module.json5`、`gecko/src/main/module.json5`
审计规则：未获 ACL 批准时，不得出现 `ohos.permission.kernel.ALLOW_EXECUTABLE_FORT_MEMORY`；
不得出现无 `reason`/`usedScene` 的 `user_grant` 权限。

| 文件 | `requestPermissions` | JIT ACL | 结论 |
|---|---|---|---|
| `entry/src/main/module.json5` | 未声明 | 未声明 | **PASS** |
| `gecko/src/main/module.json5` | 未声明 | 未声明 | **PASS** |

补充说明：
- `entry` 当前只有 `EntryAbility`，无 `requestPermissions` 字段，符合最小权限原则。
- M4 接入网络时只新增 `ohos.permission.INTERNET`（`system_grant`，无需 `reason`）。
- ACL 获批后，声明位置应在 **`entry`**（HAP 侧，最终安装主体）；`gecko` 作为 HSP 不重复声明。
  变更时必须同步更新本节与 `risk-register.md` R1 状态。

复审触发条件：新增任何权限、ACL 状态变化、应用市场政策更新。
