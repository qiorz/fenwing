# 风险登记册：Gecko for HarmonyOS

**版本**: 1.0
**日期**: 2026-11-17
**评审节奏**: 每个里程碑门禁前必审；每月例行复核一次；任一"高/高"风险触发时 48 小时内复审。

评级口径：
- **概率**：确定 / 高（>60%）/ 中高（40-60%）/ 中（20-40%）/ 低（<20%）
- **影响**：高（门禁失败或需重新立项）/ 中高（里程碑延期 >1 个月）/ 中（需降级方案）/ 低（局部返工）

---

## 3. 高风险项处置计划

### R1 — JIT 受限

| 项 | 内容 |
|---|---|
| 缓解步骤 | 1) M1 只做解释器模式；2) M1 期间提交 ACL 申请；3) 用同一组 JS 基准（SunSpider 子集 + 真实页面脚本）对比解释器/ACL 差距；4) 差距 >3× 时启动热路径优化专项 |
| 验收指标 | 解释器模式下 JS 求值往返 <50ms（plan.md 性能目标）；无 JIT 稳定运行 30 分钟 |
| 剩余风险 | ACL 被拒 + 解释器性能不足 → 触发停止条件 |
| 责任人 | 安全合规 + JS 引擎负责人 |

### R2 — 进程模型

| 项 | 内容 |
|---|---|
| 缓解步骤 | 1) M1-M5 单进程；2) 引擎内所有"进程边界"抽象成接口（`ProcessHost`），先给单进程实现；3) M6 评估 `ChildProcess`（无 UI 子进程 + IPC）是否足以承载内容进程 |
| 验收指标 | 单标签崩溃不影响 UI 进程（应用层捕获 + 重建会话） |
| 剩余风险 | 单进程下恶意页面可导致整应用崩溃 |
| 责任人 | 平台架构 |

### R3 / R11 — 商店政策

| 项 | 内容 |
|---|---|
| 缓解步骤 | 1) M2 前取得书面答复（自绘内核浏览器是否允许、是否需要额外审核）；2) 准备 ArkWeb 体验层降级方案（保留 UI/数据层，替换引擎绑定）；3) 隐私清单与权限说明随首个可演示包一起提交预审 |
| 验收指标 | 有书面结论；或有可切换的引擎抽象层 |
| 剩余风险 | 政策变化导致已投入工作不可上架 |
| 责任人 | 产品 + 法务 |

### R4 / R14 — 构建链

| 项 | 内容 |
|---|---|
| 缓解步骤 | 1) 本机只做 NAPI/HSP 构建（已验证）；2) Gecko 构建移到外部 Linux；3) 补丁按子系统拆分（构建/target、运行时、图形、网络）；4) 每个补丁附最小复现命令 |
| 验收指标 | 外部 Linux 上 `mach build --enable-project=js` 可复现；补丁应用成功率 100% |
| 剩余风险 | 外部构建机与设备环境差异导致"能编不能跑" |
| 责任人 | 构建/基础设施 |

### R5 — 渲染

| 项 | 内容 |
|---|---|
| 缓解步骤 | 1) M3 先做 SWGL 静态页；2) GLES 路径独立开关；3) XComponent 生命周期矩阵测试（创建→尺寸变化→后台→销毁→重建）；4) 黑屏时输出 EGL 错误码到 hilog |
| 验收指标 | 静态页首帧 <5s；尺寸变化后 1 帧内恢复；无持续黑屏 |
| 剩余风险 | 特定 GPU 驱动下只能软件渲染 |
| 责任人 | 图形负责人 |

### R12 — 性能

| 项 | 内容 |
|---|---|
| 缓解步骤 | 1) 建立基线（见 `performance-baseline.md`）；2) 每个门禁复测同一组指标；3) 设定回归阈值（>10% 需说明） |
| 验收指标 | 冷启动 <2s（热启动）、滚动 60fps、5 标签 <2GB（产品目标，M5 后校准） |
| 责任人 | 性能/QA |

## 4. 风险登记流程

1. **新增**：任何人在门禁评审或日常开发中发现新风险，按上表格式追加，ID 递增。
2. **升级**：概率或影响任一升到"高"，48 小时内组织复审，并在 `decision-package.md` 第 0 节标注。
3. **关闭**：必须有证据（测试报告/书面答复/构建日志），在"当前状态"列写"已关闭 + 证据位置"。
4. **与停止条件的映射**：R1/R2/R4/R5/R11 任一变为"确定 + 高"，直接触发 `decision-package.md` 第 6 节的停止/转向评估。
