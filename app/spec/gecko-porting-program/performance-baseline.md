# 性能基线：Gecko for HarmonyOS

**版本**: 1.0
**日期**: 2026-11-17
**状态**: 指标与测量方法已定义；**本阶段无实测数据**（引擎未运行，设备部署属于 Phase 9）
**适用设备**: HUAWEI MatePad Edge，HarmonyOS API 26，aarch64，tablet

---

## 1. 目的

1. 为每个里程碑提供**可复现**的性能门禁，避免"能跑但不可用"。
2. 区分"解释器基线"与"ACL+JIT 基线"，为 JIT 决策提供数据（见 `security-compliance.md` §1）。
3. 把性能回归变成可量化事件：超过阈值必须说明原因。

---

## 2. 测量环境（必须固定）

| 项 | 要求 |
|---|---|
| 设备 | MatePad Edge（API 26），关闭省电模式，屏幕亮度固定 50% |
| 温度 | 冷机启动（静置 ≥10 分钟），或记录机身温度 |
| 网络 | 固定 Wi-Fi，或使用本地静态页（离线测量） |
| 构建 | `debug` 用于功能验证；`release` 用于性能数字 |
| 版本记录 | 必须记录 `getVersion()` 的 `buildId` / `geckoVersion` |
| 采样次数 | 每指标 ≥5 次，取中位数与 P90 |

## 4. 测量方法

### 4.1 应用侧（首选，可自动化）

`entry/src/main/ets/pages/Index.ets` 已内置 M0 探测，可直接读取：

- `EngineProbeResult.elapsedMs()` → P11；
- `getVersion()` 的 `buildId` → 版本记录；
- `JsSmokePage.ets` 的 "耗时" 文本 → P3/P4。

后续在 `GeckoService` 增加统一的 `metrics()` 快照（M2），字段与上表 P1-P10 对齐。

### 4.2 系统侧（辅助）

| 指标 | 方法 |
|---|---|
| 进程 RSS | 通过 hilog 输出采样，或系统开发者选项的内存面板 |
| 启动耗时 | hilog 中 `EntryAbility` 的 `onCreate`/`onWindowStageCreate` 时间戳差 |
| 帧率 | 系统"帧率显示"开关 + 录屏抽帧 |
| 崩溃 | `hdc` 侧 faultlog（仅在 Phase 9 验证时使用） |

> 注意：本项目不允许把"独立可执行文件"作为测量工具（EPERM 约束），所有采样必须走应用内或系统能力。

### 4.3 记录模板

每次测量在本文末尾追加一行：

```text
| 日期 | buildId | 指标 | 中位数 | P90 | 设备状态 | 备注 |
```

## 5. 回归策略

| 变化 | 允许的性能波动 | 超出后的动作 |
|---|---|---|
| 普通提交 | ±5% | 说明原因，不需要专项 |
| 补丁/基线 rebase | ±10% | 必须给出对比报告，门禁评审确认 |
| 里程碑交付 | 不得低于目标值 | 门禁不通过 |

- 任一红色指标（低于目标 20% 以上）触发 `risk-register.md` R12。
- 解释器模式与 ACL+JIT 模式必须**分开记录**，不得混用同一基线。

- 上述体积与会话内存无关，但可作为 M0 交付的体积基线。
